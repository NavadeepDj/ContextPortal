## OpenWiki

This repository has a generated `openwiki/` evidence index. It is optional just-in-time context, not required startup reading.

- Treat source code and tests as authoritative. A brief's unknowns and review items are verification gaps, not automatic requirements.
- Prefer the narrowest quiet validation that proves the changed behavior. Preserve complete failure output.

The scheduled OpenWiki GitHub Actions workflow refreshes the repository wiki. Do not hand-edit generated OpenWiki pages unless explicitly asked; prefer updating source code/docs and letting OpenWiki regenerate.

## Command Execution & Approval Rule

Before asking for permission to execute any terminal/shell command or consequential action, you must first explain:
1. **What is going on**: A summary of current context and what was just completed.
2. **What command is being run**: The exact command string and its flags.
3. **Why it is being run / How it helps**: The specific rationale and how it advances the project goals.
4. **Consequences & Risks**: Any side effects (e.g. disk writes, network access, environment changes).
